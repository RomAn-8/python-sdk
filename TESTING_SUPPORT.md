# Инструкция по тестированию команды /support

## Подготовка

### 1. Убедитесь, что MCP сервер запущен

В терминале в директории `python-sdk`:

```bash
cd D:\MyWork\MyRepositories\python-sdk
uv run --with mcp mcp-server-demo/mcpserver_quickstart.py
```

Сервер должен запуститься на `http://127.0.0.1:8000/mcp`

### 2. Убедитесь, что бот запущен

В другом терминале в директории `nikita_ai`:

```bash
cd D:\MyWork\MyRepositories\nikita_ai
# Запустите бота (команда зависит от вашей настройки)
```

### 3. Проверьте, что документация проиндексирована

Убедитесь, что файл `nikita_ai/docs/club-rules.md` существует и эмбеддинги созданы для RAG.

## Тестирование команды /support

### Базовое использование

В Telegram боте отправьте команду:

```
/support <ваш вопрос>
```

## 🎯 Вопросы для проверки интеграции с Google Sheets

Эти вопросы **обязательно** должны использовать данные из Google Sheets:

### Тест 1: Проверка данных пользователя
**Шаги:**
1. Зарегистрируйтесь: `/register Иван Иванов +79991234567`
2. Задайте вопрос: `/support какой у меня статус?`

**Ожидаемый результат:**
- В ответе должны быть данные из Google Sheets:
  - ФИО: Иван Иванов
  - Статус: active (или blocked, если заблокирован)
  - Дата регистрации

### Тест 2: Проверка активных записей
**Шаги:**
1. Зарегистрируйтесь (если еще не зарегистрированы)
2. Запишитесь на тренировку: `/train_signup 15-02-2026 18:00`
3. Задайте вопрос: `/support когда у меня следующая тренировка?`

**Ожидаемый результат:**
- В разделе "📅 Данные регистрации" должны быть:
  - reg_id записи
  - Дата: 15-02-2026
  - Время: 18:00
  - Статус: Активна

### Тест 3: Персонализированный вопрос о переносе
**Шаги:**
1. Убедитесь, что у вас есть активная запись
2. Задайте вопрос: `/support можно ли перенести мою запись?`

**Ожидаемый результат:**
- Ответ должен содержать:
  - Информацию о правилах переноса (из RAG документации)
  - **Конкретные данные вашей записи** из Google Sheets:
    - reg_id
    - Текущая дата и время
    - Статус
  - Инструкции, как перенести (команда `/train_move`)

### Тест 4: Вопрос о всех записях
**Шаги:**
1. Создайте несколько записей (если возможно)
2. Задайте вопрос: `/support какие у меня активные записи?`

**Ожидаемый результат:**
- Должны быть перечислены все активные записи из Google Sheets
- Для каждой записи: reg_id, дата, время, статус

### Тест 5: Вопрос о статусе записи
**Шаги:**
1. Создайте запись
2. Задайте вопрос: `/support какая у меня запись на 15-02-2026?`

**Ожидаемый результат:**
- Должна быть показана конкретная запись из Google Sheets
- Дата, время, статус должны совпадать с данными в таблице

### Тест 6: Вопрос о переносе с конкретной датой
**Шаги:**
1. Убедитесь, что у вас есть активная запись
2. Задайте вопрос: `/support могу ли я перенести запись на 20-02-2026?`

**Ожидаемый результат:**
- Ответ должен учитывать:
  - Правила переноса (из документации)
  - **Вашу текущую запись** из Google Sheets
  - Инструкции по переносу

### Тест 7: Вопрос о блокировке
**Шаги:**
1. Зарегистрируйтесь
2. (Опционально) Заблокируйте себя через MCP (для теста)
3. Задайте вопрос: `/support могу ли я записаться на тренировку?`

**Ожидаемый результат:**
- Если статус "blocked" в Google Sheets:
  - Бот должен сообщить, что пользователь заблокирован
  - Объяснить, почему нельзя записаться
- Если статус "active":
  - Бот должен дать инструкции по записи

### Тест 8: Комплексный вопрос с контекстом
**Шаги:**
1. Зарегистрируйтесь и создайте запись
2. Задайте вопрос: `/support я новичок, у меня запись на завтра, что мне нужно знать?`

**Ожидаемый результат:**
- Информация для новичков (из RAG документации)
- **Данные вашей записи** из Google Sheets:
  - Дата и время тренировки
  - reg_id
- Что взять с собой
- Правила клуба

## Что проверять в ответах

### 1. Качество ответа
- Ответ должен быть релевантным вопросу
- Информация должна быть точной и соответствовать документации
- Ответ должен быть понятным и структурированным

### 2. Источники (если реализовано)
- Должны показываться источники информации (doc_name, chunk_index, score)
- Должны быть короткие цитаты из документации

### 3. Данные регистрации (если пользователь зарегистрирован)
- Должны показываться данные о записях пользователя (reg_id, дата/время, статус)
- Информация должна быть актуальной из Google Sheets

### 4. Контекст пользователя
- Бот должен учитывать контекст пользователя (его записи, статус)
- Ответы должны быть персонализированы, если это уместно

## Типичные проблемы и решения

### Проблема: "Релевантная документация не найдена"
**Решение:**
- Проверьте, что файл `club-rules.md` находится в `nikita_ai/docs/`
- Убедитесь, что эмбеддинги созданы и проиндексированы
- Проверьте настройки RAG в коде бота

### Проблема: "MCP сервер недоступен"
**Решение:**
- Убедитесь, что MCP сервер запущен
- Проверьте, что он слушает на `http://127.0.0.1:8000/mcp`
- Проверьте переменную окружения `MCP_SERVER_URL` в боте

### Проблема: "Ошибка при получении данных пользователя"
**Решение:**
- Проверьте, что service account добавлен в редакторы Google Sheets
- Убедитесь, что переменные окружения настроены в `.env` файле MCP сервера
- Проверьте, что пользователь зарегистрирован через `/register`

### Проблема: Ответы не соответствуют документации
**Решение:**
- Проверьте, что файл `club-rules.md` содержит актуальную информацию
- Убедитесь, что эмбеддинги пересозданы после обновления документации
- Проверьте настройки LLM (модель, температура, промпты)
